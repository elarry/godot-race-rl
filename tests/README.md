# Godot Race RL Test Playbook

This folder hosts all automated and manual verification assets for the project. Keep it as the single source of truth for how to validate code before opening a PR.

## Directory Layout
- `test_*.gd` – GutTest scripts targeting gameplay systems:
  - `test_car_surface_detection.gd` – grass vs. tarmac color/pixel detection on `car.gd`.
  - `test_car_tire_collision.gd` – tire barrier impulse response on `car.gd`.
  - `test_car_rl_mode.gd` – `rl_mode`/`set_rl_action()` input branching and `had_collision_this_frame` on `car.gd`.
  - `test_car_track_sprite_lookup.gd` – bounded retry behavior of the Track-sprite lookup on `car.gd`.
  - `test_car_sensors.gd` – egocentric observation extraction on `scripts/rl/car_sensors.gd`: ego-state (forward/lateral/angular velocity, last steer/throttle-brake), wall/grass raycast distances, the surface-grip scalar, and opponent-perception (k-nearest cars detected via the ray fan, car-relative position/heading/velocity).
  - `test_reward_calculator.gd` – hand-computed reward terms on `scripts/rl/reward_calculator.gd`.
  - `test_checkpoint_manager.gd` – per-car gate ordering, lap-wrap, race-progress ranking, and stuck/grass/timeout timers on `scripts/rl/checkpoint_manager.gd` (one shared gate sequence, N cars tracked independently).
  - `test_outer_wall_boundary.gd` – wall geometry generated by `outer_wall_boundary.gd`.
  - `test_tire_barrier_scene.gd` – tire barrier scene structure (`scenes/tire_barrier.tscn`).
  
  Name new files after the system under test.
- `run_gut.sh` – Convenience wrapper that launches the Godot CLI runner headlessly with the correct flags.
- `scripts/rl/rl_bridge.gd` (WebSocket transport) has no `test_*.gd` file — a `TCPServer`/`WebSocketPeer` isn't practical to unit test in GUT's synchronous runner. It's instead verified live: launch `scenes/rl/rl_training.tscn` headless (`godot --headless --path . scenes/rl/rl_training.tscn`) and drive it with a real WebSocket client (`uv run --with websocket-client python3 <script>`), asserting on the batched JSON replies (`obs`/`reward`/`terminated`/`truncated`/`info` are each length-N arrays, one entry per car — see `specs/rl-multi-car/PLAN.md`).

## Automated Tests (GUT)
1. Ensure the Godot binary path is available. The project defaults to `/Applications/Games/Godot.app/Contents/MacOS/Godot`; override via `GODOT_PATH=/custom/Godot`.
2. From the repo root run:
   ```bash
   tests/run_gut.sh
   ```
   This expands to:
   ```bash
   ${GODOT_PATH:-/Applications/Games/Godot.app/Contents/MacOS/Godot} \
     --headless --path . \
     --script res://addons/gut/gut_cmdln.gd -- \
     -gdir=res://tests -gexit
   ```
   `-gexit` forces the runner to terminate once tests finish so CI never hangs.
3. Inspect the summary. Any “orphans” usually mean a test forgot to free nodes; fix those before shipping.
4. For selective runs use `tests/run_gut.sh -gselect car_surface` or `-gunit_test_name detection`.

### Writing New Gut Tests
- Extend `GutTest`, use explicit type hints, and `preload` gameplay scripts so constants satisfy Godot’s static typing rules.
- Prefer tiny helper factories (see `_make_track_image` in `test_car_surface_detection.gd`).
- Free spawned nodes (`.free()`) in helpers to keep the orphan count at zero.
- Place new suites alongside the system under test and register their `.gd.uid` files as usual so the editor sees them.
- Tests that need real physics (`move_and_slide()`, collisions) must add the car via `add_child_autofree()` so it has a physics space; also pre-bind `car.track_sprite` to a dummy `Sprite2D` before adding it, otherwise `_ready()`'s Track-sprite lookup emits a one-time warning (harmless, but GUT reports it as a failure) — see `test_car_rl_mode.gd`/`test_car_track_sprite_lookup.gd`.
- Conversely, a car used only as a **data holder** (e.g. as the `car` argument to a `CarSensors` pure function, not to exercise its own physics) must *not* be added to the tree via `add_child_autofree()`. Doing so makes the engine call the car's real `_physics_process()` every frame during `wait_physics_frames()`, which silently overwrites whatever `velocity`/`rotation`/`current_speed` the test just hand-set (friction/drift math pulls `velocity` toward what `current_speed` implies, not the other way around). Construct it with `CAR_SCRIPT.new()` and free it manually instead — see `test_car_sensors.gd`'s opponent-perception tests, where only the *rays* and *opponent* bodies need to be in the tree.
- After adding a script with a new `class_name` (e.g. `CarSensors`), run `godot --headless --editor --quit --path .` once to refresh `.godot/global_script_class_cache.cfg`, or GUT/GDScript won't resolve the type name.

## Manual Testing
- Feel-focused checks (drift tuning, collision responses, UI feedback) are validated in-editor against `scenes/main.tscn`; there is no dedicated manual test scene.
- When adding new feel-dependent gameplay, outline reproduction steps and observations in your PR.
- If a manual scenario uncovers a deterministic bug, codify it as an automated GUT test to prevent regressions.

## Reporting Results
1. After every meaningful change, run `tests/run_gut.sh` and confirm the summary shows all scripts passing with zero orphans.
2. For PRs, quote the pass/fail summary and describe any manual checks performed, attaching screenshots/GIFs if visuals changed.
